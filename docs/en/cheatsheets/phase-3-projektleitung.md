# Cheat Sheet Phase 3 – Project Management { .cheatsheet }

After this phase you can steer AI projects in a phase-appropriate way, formulate requirements measurably, set up evaluation bindingly and accompany adoption effectively.

## Key Messages

1. AI projects are research projects: 30–40 % of pilot projects do not reach production — failures are project risks, not a disgrace.
2. Each phase needs hard stop criteria, otherwise every PoC flows into the next step.
3. Requirements are only useful when they are measurable — "measure" or "demonstrate" must appear, otherwise it is hope.
4. Probabilistic systems can never be "always right" — minimum recall, maximum false-positive rate and clarification rate replace this promise.
5. Evaluation without consequence is theatre — whoever accepts no "not passed → back to start" has no evaluation.
6. AI introduction almost never fails because of technology but because of the change programme — training, communication and champions decide.

## Common Mistakes

- **Shouting "it works" after the PoC** — a functioning PoC is not a production-ready system.
- **Defining requirements without acceptance criteria** — "the AI should detect contract risks" is wish, not requirement.
- **Starting evaluation only at go-live** — whoever develops without a test set tests their own opinion in the end.
- **Selling demo examples as quality proof** — without a reproducible gold set every success story is anecdotal.
- **Planning the change programme only after technology** — whoever pushes training and communication afterwards loses acceptance in the pilot.

## Clarify Before the Next Session

- Which stop criteria apply at the end of the current phase transition (PoC → Pilot → Production)?
- Which acceptance criteria are already measurably formulated in the backlog — where are they still missing?
- Who provides ground truth for the gold set, and how many test cases exist per use case?
- Which stakeholder groups must be informed, trained or involved before the next milestone?
- Which organisational risks (resistance, shadow AI, role ambiguity) have become visible in the pilot?
- How is escalation arranged when evaluation, data protection or operations deliver a "no"?
