# Change Management and AI Adoption

[← back to topic list](../themenliste.md)

## Learning Objective

Communicate an AI introduction with [change management](../glossar.md#change-management) so that it is perceived as support and not as a threat.

## Fears and Resistance

- **Job loss** — most common concern
- **Loss of control** — "the thing decides"
- **Incompetence** — "I don't understand this"
- **Loss of meaning** — "just pressing a button"
- **Legal uncertainty** — "who is liable when the AI errs?"

## AI as Support, Not Staff Reduction

Especially when introducing a [copilot](../glossar.md#copilot), the communication must make the supportive character clear.

Communication rules:

- AI takes over **tasks**, not **roles**
- Whoever hands off tasks gains time for value-adding activity
- Do not promise waves of layoffs (but expansion)

## Communication About Opportunities AND Limits

Whoever only sells opportunities loses credibility at the first mistake. Whoever names both regains it.

## Training Different User Groups

- **Power users** — [prompt engineering](../glossar.md#prompt-engineering), tool understanding
- **Casual users** — what the AI can and cannot do
- **Managers** — output evaluation, risk interpretation
- **Privacy workforce** — [compliance](../glossar.md#compliance) obligations

## AI Champions and Multipliers

One person per team who:

- Proposes new use cases
- Coaches colleagues
- Forwards feedback to roles with clearly regulated [accountability](../glossar.md#verantwortlichkeit)

## Usage Guidelines

Document clearly:

- Which inputs are allowed (no PII in public tools)
- Which outputs may be used how
- Which AI tools may be used

## [Shadow AI](../glossar.md#shadow-ai)

Employees use AI tools **secretly**. Three counter-measures:

1. Make allowed tools easily accessible
2. Create incentives to talk openly about it
3. Offer training that creates added value

## Process Change Instead of Only Tool Introduction

The AI is the means, not the end. Question: which **process** changes — and is it sensible at all?

## Measuring Actual Usage

- Number of active users per quarter
- Number of requests per user
- "Helpful / not helpful" ratio
- Time spent in the tool

When metrics stagnate: it is not the tool that failed, but the change programme.

## [Responsible AI](../glossar.md#responsible-ai) Culture

- Learn from mistakes instead of blame
- Openness about uncertainties
- Time and budget for [evaluation](../glossar.md#evaluation)
- Ethical discussion as a regular appointment

!!! tip "Practical tip"
    The introduction has failed when the tool costs a lot and is used little. That almost never has technical reasons.
